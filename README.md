# PaymentCore

Учебный банковский backend на C#: пользователи, счета, пополнение и переводы между счетами. Проект про то, как надёжно работать с деньгами: деньги не должны теряться, дублироваться или появляться из ниоткуда.

> Это учебный проект. Реальных карт, денег и подключения к банкам здесь нет.

## Стек

- C#, .NET 10, ASP.NET Core (контроллеры)
- Entity Framework Core + PostgreSQL
- Docker / Docker Compose
- xUnit (юнит-тесты)
- Scalar (интерактивная документация API)

## Архитектура

Четыре слоя, зависимости направлены внутрь:

- `PaymentCore.Domain` - сущности и бизнес-правила (`User`, `Account`, `LedgerEntry`). Ни от чего не зависит.
- `PaymentCore.Application` - сервисы и сценарии (создать счёт, пополнить, перевести). Работает с базой через интерфейс `IAppDbContext`.
- `PaymentCore.Infrastructure` - `AppDbContext`, EF Core, миграции, PostgreSQL.
- `PaymentCore.Api` - контроллеры, настройка DI, запуск приложения.

## Ключевые идеи

- **Проводки (ledger).** Каждое изменение баланса записывается как `LedgerEntry`. Зачисление хранится как положительное число, списание как отрицательное. Сумма всех проводок равна сумме балансов.
- **Атомарный перевод.** Списание, зачисление и обе проводки сохраняются одним `SaveChangesAsync`, то есть в одной транзакции: записывается всё или ничего.
- **Типы данных.** Деньги хранятся в `decimal` (`numeric` в PostgreSQL), идентификаторы в `Guid` (`uuid`): без ошибок округления и угадываемых id.
- **Защищённые сущности.** У свойств `private set`, изменения идут только через методы (`Deposit`, `Withdraw`) с проверками.
- **Понятные ошибки.** Перевод на тот же счёт, несуществующий счёт и нехватка средств возвращают 400/404 с текстом, а не 500.

## Запуск

Нужны .NET 10 SDK и Docker.

```bash
# 1. База данных
docker compose up -d

# 2. Таблицы (миграции)
dotnet ef database update --project src/PaymentCore.Infrastructure --startup-project src/PaymentCore.Api

# 3. API
dotnet run --project src/PaymentCore.Api
```

Документация и тестовые запросы: http://localhost:5266/scalar/v1

> Пароль к базе в `docker-compose.yml` и `appsettings.json` учебный, только для локальной разработки.

## Эндпоинты

- `POST /users` - создать пользователя
- `POST /accounts` - создать счёт
- `POST /accounts/{id}/deposit` - пополнить счёт
- `GET /accounts/{id}` - баланс счёта
- `POST /transfers` - перевод между счетами

## Тесты

```bash
dotnet test
```

Покрыта доменная логика `Account` (пополнение, списание, защита от ухода в минус).

## Планы

- Банковские карты: номер по алгоритму Луна, в базе только последние 4 цифры, CVV не хранится
- Дебетовые и упрощённые кредитные карты (лимит, долг, проценты, льготный период)
- История проводок и статистика трат с графиками
- Защита от одновременных переводов (конкурентность) и идемпотентность
- JWT-авторизация
- Тесты на сервисы и интеграционные тесты
